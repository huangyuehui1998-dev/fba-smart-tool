本文档描述主工作流第五步「报关资料」在 FBA Smart Tool 中的定位、前后端架构、
数据装配与合并算法、净重/金额计算规则、Excel 模板写入映射及 API 契约，
供开发维护与现场使用参考。

与 Step 4（货件校验）、Step 4.5（货代发票）紧密衔接；产出形态为
「预览 + 可编辑 + 导出 .xlsx」，仿 Step 4.5 交互模式。


================================================================================
一、模块定位与业务价值
================================================================================

【解决什么问题】
  跨境电商 9810 合并报关需同时提交：报关单、申报要素、发票、箱单、合同、
  代理报关委托书等 7 个 sheet（含 2 个静态说明 sheet）。手工从发货表、
  发票、主数据多处复制易错、格式不统一。本模块在一键预览后允许微调，
  再导出符合国家模板格式的 .xlsx。

【前置条件】
  - Step 4 货件校验必须通过（step4Ok = true）
  - workflow 中须含 shipments[].parsed_shipment（CSV 解析后的箱明细）
  - 订单号/合同号：页面手填（不自动从货件号推断）
  - 出口商主体：从「出口商档案」选择（支持多家、可设默认）

【两条数据来源（A/B 切换）】

  来源 A — invoice（复用 Step 4.5 发票明细）
    直接读取 invoiceDraft.cells 中按行聚合的发票 line items
    （含 HS、品牌、申报单价、数量等）。适合已在 4.5 核对过货值的用户。

  来源 B — shipment（仅 Step 4，自行重算）
    从 parsed_shipment 按 SKU 聚合，再查产品库 + 主数据库补 HS/品牌/货值，
    不调 AI。等价于 invoice_automation._customs_by_sku 的第 2 层（产品库）。

【多 SKU 合并规则】
  不论 A/B，最终商品行按「中文品名 + HS 编码」合并为一个报关项号；
  数量、金额、箱数、毛重、净重累加；单价 = 合并后总额 / 合并后数量。

【产出物】
  - 预览：JSON 结构化数据（CustomsPackageData），前端 6 个 Tab 可编辑
  - 导出：基于 backend/templates/customs/报关资料模板.xlsx 填充后的 .xlsx

三、工作流与用户操作路径
================================================================================

【主流程步骤】

  Step 1 录入 → Step 2 排箱 → Step 3 导出 → Step 4 回传校验
      → Step 4.5 发票（可选，来源 A 需要）
      → Step 5 报关资料

【Step 5 页面操作序列】

  1. 进入 Step 5（Header 点击或 Step 4.5「Step 5 报关资料」）
  2. 选择出口商（下拉，数据来自 /api/exporters）
  3. 手填订单号/合同号（必填，如 DEMO-ORDER）
  4. 选择数据来源：
       A · 发票明细 — 需 workflow.invoiceDraft 非空
       B · 发货重算 — 仅需 Step 4 通过
  5. 点击「生成预览」→ POST /api/customs/preview
  6. 在 Tab（报关单/申报要素/发票/箱单/合同/委托书）中编辑字段
  7. 点击「生成报关资料 (.xlsx)」→ POST /api/customs/export（带编辑后 data）
  8. 浏览器下载 报关资料_{订单号}.xlsx

【侧栏出口商档案（独立可测）】

  路径：侧边栏 → 系统设置 → 出口商档案
  操作：列表 / 新增 / 编辑 / 删除 / 设为默认
  持久化：app_data/config/exporter_profiles.json

  默认出厂档案（backend/config/exporter_profiles.default.json）：

    name: 武汉花笨橙电子商务有限公司
    credit_code: 91420113MACWNNKU99

================================================================================
五、完整计算逻辑与公式记录
================================================================================

────────────────────────────────────────────────────────────────────────────
5.1  workflow → 货件对（pairs_from_workflow）
────────────────────────────────────────────────────────────────────────────

  输入：workflow_json.shipments[] 每项含
        shipment_id, warehouse, parsed_shipment

  处理：csv_shipment_from_dict(parsed_shipment) → CsvShipment
        包装为 ShipmentPair(shipment_id, warehouse_code, csv, pdf_stub)

  输出：List[ShipmentPair]；box_items 为空则跳过

────────────────────────────────────────────────────────────────────────────
5.2  来源 B — 按 SKU 展开（_sku_rows_from_pairs）
────────────────────────────────────────────────────────────────────────────

  对每个 ShipmentPair.csv：

  (1) 按 SKU groupby box_items
  (2) 对每个 SKU：
        boxes     = 该 SKU 出现的箱号列表（去重）
        qty       = Σ 该 SKU 在 box_items 中的「数量」
        box_count = len(boxes)
        gross_kg  = Σ spec_map[箱号].实重(kg)  （spec 来自 box_specs）

  (3) 产品信息 _catalog_hints(sku) 合并顺序：
        product_catalog.to_invoice_hints()
        → master_db.get_product_by_sku（中文品名、hs_code、brand、unit_weight…）
        → lookup_customs_name(sku)

  (4) 单价 unit_price：
        优先 catalog/主数据「单个货值」；无则 0

  (5) 行金额 amount：
        amount = round(unit_price × qty, 2)   （unit_price 为 0 则 amount=0）

  (6) 行净重 net_kg（见 5.4）

  输出：raw_rows[]，每 SKU 一行（尚未合并）

────────────────────────────────────────────────────────────────────────────
5.3  来源 A — 发票草稿展开（_rows_from_invoice_draft）
────────────────────────────────────────────────────────────────────────────

  输入：invoiceDraft.cells[]，每项含 cell（如 B12）、field_key、value

  处理：
    - 按 cell 行号聚合为 by_row[row_num][field_key] = value
    - 跳过无 sku 且无 chinese_name 的行
    - qty = total_qty 或 qty；≤0 跳过
    - declared = declared_price 或 unit_price
    - amount = total_declared_value_usd，或 round(declared × qty, 2)
    - gross = box_weight 或 total_weight_kg
    - net：有 unit_weight_kg 则 unit_weight_kg × qty，否则 gross × 净重系数

  输出：raw_rows[]（结构同 B，便于统一合并）

────────────────────────────────────────────────────────────────────────────
5.4  净重估算（优先级）
────────────────────────────────────────────────────────────────────────────

  配置项：user_settings.json → parameters.customs_net_weight_ratio
          默认 0.9（DEFAULT_NET_RATIO）

  【SKU 行级 net_kg】

    优先级 1 — Step 1 主数据「单个重量(kg)」
      unit_net = step1_rows 中该 SKU 的 单个重量(kg)
      net_kg   = round(unit_net × qty, 2)

    优先级 2 — 主数据库 unit_weight（单品净重，Fee Preview 字段）
      net_kg   = round(unit_weight × qty, 2)

    优先级 3 — 毛重 × 系数
      net_kg   = round(gross_kg × customs_net_weight_ratio, 2)

  【来源 A 补充】
    若 invoice cell 有 unit_weight_kg：
      net_kg = round(unit_weight_kg × qty, 2)
    否则若 gross > 0：net_kg = round(gross × 系数, 2)

  【页面覆盖】
    用户在 Step 5 编辑 lines[].net_kg 或 total_net_kg
    → 导出时 POST body.data 直接携带修改值（不再重算）

────────────────────────────────────────────────────────────────────────────
5.5  多 SKU 合并（_merge_rows）
────────────────────────────────────────────────────────────────────────────

  合并键：key = (chinese_name.strip(), hs_code.strip())
  跳过：中文品名为空的行

  对同一 key 累加：
    qty, amount, box_count, gross_kg, net_kg
  保留：首行的 unit、model、material、purpose；brand 取首个非空

  合并后重算：
    unit_price = round(amount / qty, 2)    若 qty=0 则 0
    seq        = 1, 2, 3 …（按合并后顺序）
    declare_elements = _build_declare_elements(...)

  申报要素串格式：
    "1|2|{用途或材料或宠物用}|品牌：{品牌}牌|型号：{型号}"
    示例：1|2|宠物用|品牌：DEMO牌|型号：无型号

────────────────────────────────────────────────────────────────────────────
5.6  汇总字段（build_customs_data）
────────────────────────────────────────────────────────────────────────────

  total_qty    = round(Σ lines[].qty, 2)
  total_amount = round(Σ lines[].amount, 2)
  total_gross  = round(Σ lines[].gross_kg, 2)
  total_net    = round(Σ lines[].net_kg, 2)

  total_pieces（报关单「件数」= 总箱数）：
    优先 _count_total_boxes(pairs)：
      对所有货件 (shipment_id, 箱号) 去重计数
    若结果为 0：fallback Σ lines[].box_count

  若 total_gross 仍为 0 且有 pairs：
    total_gross = Σ 全部 box_specs.实重(kg)
    若 total_net 仍为 0：total_net = round(total_gross × 系数, 2)

  remarks（报关单备注 B16）：
    "订单编号：{order_no}。仓库编码：{wh1，wh2…}。FBA编码：{sid1，sid2…}。"
    仓库 / FBA 号从 pairs 去重按出现顺序拼接

  main_goods_name = 前 3 个合并品名用「、」连接
  hs_codes_summary = 所有 HS 去重后用「、」连接

  amount_in_words = amount_to_english_words(total_amount)
    先 round(total_amount, 2)，拆分为整数美元 + 美分（0–99）：
    - 美分为 0："{DOLLARS} US DOLLARS ONLY"
    - 美分非 0："{DOLLARS} US DOLLARS AND {CENTS} CENTS ONLY"
    例：16334.60 → "SIXTEEN THOUSAND THREE HUNDRED THIRTY FOUR US DOLLARS AND SIXTY CENTS ONLY"
    例：16334.00 → "SIXTEEN THOUSAND THREE HUNDRED THIRTY FOUR US DOLLARS ONLY"
    英文金额与数字格 total_amount 严格对应，避免报关行退单。

────────────────────────────────────────────────────────────────────────────
5.7  默认日期（default_dates）
────────────────────────────────────────────────────────────────────────────

  基准日 = 当天（服务器本地 date.today()）

  字段                          默认值
  ─────────────────────────────────────────────────────────
  export_date                   当天
  declare_date                  当天
  invoice_date                  当天
  contract_date                 当天
  packing_date                  当天
  shipment_deadline             当天 + 15 天
  entrust_import_export_date    当天 + 1 天
  entrust_doc_received_date     当天
  entrust_sign_date             当天 - 1 天

  页面可改 dates.*；导出时 _parse_date 解析 YYYY-MM-DD 为 datetime.date 对象
  写入 openpyxl（不写 ISO 字符串），Excel 识别为日期并套用模板单元格格式；
  无法解析的日期跳过写入（不写纯文本）。

  总计/合计格：_set 直接赋 cell.value = 计算结果，覆盖模板原有 SUM 等公式
  （insert_rows 后静态公式引用范围易错乱，以程序内汇总值为准）。

────────────────────────────────────────────────────────────────────────────
5.8  overrides 应用（apply_overrides）
────────────────────────────────────────────────────────────────────────────

  头字段：order_no, buyer, trade_term, total_pieces, total_gross_kg,
          total_net_kg, total_qty, total_amount, remarks, amount_in_words,
          main_goods_name, dest_country, trade_country

  dates：dict 合并覆盖

  lines：按 seq 匹配，覆盖 chinese_name, hs_code, qty, unit, unit_price,
         amount, brand, model, declare_elements, box_count, gross_kg, net_kg

六、Excel 模板与 Cell Map（openpyxl 1-indexed）
================================================================================

【模板来源】
  旧版国家模板 .xls（如 DEMO-ORDER-合并报关-9810-报关资料.xls）

  backend/templates/customs/报关资料模板.xlsx

  运行时：load_workbook(模板) 作基底，只写动态单元格；sheet 1「填制规范」、
          sheet 内静态说明 URL 等不做修改。

  idx 4  箱单          动态
  idx 5  合同          动态
  idx 6  委托书        动态

  写入合并单元格时：_top_left_cell 定位合并区左上角再赋值。
  写入总计/合计时：cell.value = 数值，覆盖模板公式（见 §5.7）。

七、API 契约
================================================================================

【报关】

  POST /api/customs/preview
    Body: CustomsPreviewRequest
      source: "invoice" | "shipment"
      exporter_id?: string
      order_no: string
      dates?: Record<string, string>
      overrides?: object
      workflow_json: { input_rows, shipments, box_editor, forwarder, ... }
      invoice_draft?: object   （source=invoice 时必填）
    Response: { ok: true, data: CustomsPackageData }

  POST /api/customs/export
    Body: CustomsExportRequest（同上 + data?: 编辑后完整预览）
      若带 data：直接使用前端编辑结果 + overrides，不再全量重算
      否则：同 preview 逻辑 build 后导出
    Response: application/vnd.openxmlformats... 附件
              文件名 报关资料_{order_no}.xlsx

【出口商档案】（routers/config.py）

  GET    /api/exporters              → { profiles: [...] }
  PUT    /api/exporters/{id}         → 新增/更新
  DELETE /api/exporters/{id}
  POST   /api/exporters/active       → body { id } 设默认

  持久化路径：app_data/config/exporter_profiles.json
  结构：
    {
      "active_id": "huabenchen",
      "profiles": [
        { "id", "name", "credit_code", "address", "tel",
          "signed_at", "domestic_source" }
      ]
    }

【常见错误】

  400 来源 A 需要发票草稿  → 先完成 4.5 或改选 B
  404 未找到出口商        → 侧栏新增出口商或恢复默认配置
  500 模板不存在          → 运行 convert_customs_template.py

十一、计算示例（心算核对用）
================================================================================

  假设两 SKU 合并前：
    SKU-A  中文品名=宠物垫  HS=6307909000  qty=100  unit_price=10  gross=50kg
           step1 单重=0.4kg → net = 40kg
    SKU-B  中文品名=宠物垫  HS=6307909000  qty=80   unit_price=10  gross=40kg
           无单重 → net = 40 × 0.9 = 36kg

  合并后 1 项：
    qty=180, amount=1800, unit_price=10, box_count=累加, gross=90, net=76
    seq=1, declare_elements 按合并行品牌/用途生成

  总件数：若两货件共 115 个物理箱 → total_pieces=115（与 SKU 无关）

  备注：订单编号：DEMO-ORDER。仓库编码：VGT2，SCK4。FBA编码：FBA-DEMO，…。
