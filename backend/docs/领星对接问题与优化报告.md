### 已发现问题

1. **领星 QPS=1**  
   - 现象：全量 Listing/库存必须分页 + 请求间隔 ≥1s，进度条不能假满。  
   - 文件：`backend/fba_tool/lingxing_mcp_client.py`（节流）、`lingxing_sync.py`（按页 emit percent）。  
   - 影响：约十几次 HTTP，同步约 20–40 秒；SKU 变多后会线性变长。  
   - 优先级：P0 已按串行实现。

2. **Listing 标签工具无权限；跟卖/买家之声/自定义报表为空**  
   - 现象：标签类工具返回 `error_details.code=8002`；跟卖/店铺监控/买家之声/自定义报表为空。  
   - 影响：第一期不同步这些工具，失败记入 `lingxing_sync_diff` 后继续。  
   - 优先级：P2（账号权限，非代码）。

3. **关键词/竞品监控是钓鱼钩残留**  
   - 现象：监控关键词与 示例品牌（DemoBrand） 宠物 Listing 不是一条品线。  
   - 影响：同步时不得当作本店竞品。第一期不同步竞品/关键词工具。  
   - 优先级：P1 产品规则。

4. **`patch_product_field` 清空字段修不掉**  
   - 现象：`overwrite=False` 时 `_pick_merge` / `_pick_merge_float` 空值不会覆盖旧值。  
   - 文件：`backend/fba_tool/master_db.py` `patch_product_field`、`_pick_merge`。  
   - 影响：主数据页「清空单元格」无效（评审日志 P1）。  
   - 优先级：P1，独立修复，不在本期改合并语义。

5. **发票/报关仍可能读 `产品信息表.csv`**  
   - 现象：主库改了 HS 码，CSV 目录未改则两边不一致。  
   - 影响：Step 发票/报关与 SQLite 双源。  
   - 优先级：P1，第四期统一产品目录。

6. **GitHub / 领星密钥不得进 Git、不得打进便携包**  
   - 现象：密钥在全局 `mcp.json` 与 `app_data/config/lingxing.json`（已 gitignore `app_data/`）。  
   - 文件：`.gitignore`；侧栏保存走 `PUT /api/lingxing/settings`。  
   - 优先级：P0 已隔离。打包脚本若拷贝 `app_data` 需再排除 `lingxing.json`。

7. **主库连接未显式 close**  
   - 现象：`_connect()` + `with` 依赖上下文退出 close（评审日志 INFO）。  
   - 文件：`backend/fba_tool/master_db.py`。  
   - 优先级：INFO。WAL 下可接受；长期可改为连接池。

8. **FBA 库存行数与 Listing fulfillable 对不上**  
   - 现象：实测库存快照与 Listing 侧 fulfillable 合计是不同视图。  
   - 影响：断货提示以 `lingxing_replenish` / `lingxing_fba_stock` 为准。  
   - 优先级：P2 文档化。

11. **多平台店铺 `store_id` 是雪花 ID，不能当 Amazon `sid`**  
    - 现象：第一次同步把 `store_id=100000000000000001` 当成 sid，FBA 库存/补货变成 0 行；店铺显示 4 家重复。  
    - 文件：`lingxing_sync.py` `_amazon_sid` / `shop_to_row`。只认 `sid`/`s_id`（如 9001/9002）。  
    - 优先级：P0 已修。

12. **分页 offset 是行偏移（从 0 起），不能 +1 当页码**  
    - 现象：`erp_listing` schema「分页偏移量，起始为0」。按页码 +1 会几乎重复拉同一页，Listing upsert 150 但唯一 SKU 约 50。  
    - 文件：`lingxing_mcp_client.py` `iter_pages` 改为 `offset += len(rows)`。  
    - 优先级：P0 已修。

13. **产品表现 `sort_field`**  
    - 现象：schema 写 `sales_amount`，ASIN 汇总实际要 `amount`，否则内层 `code=0` 空列表。`sids` 必须是逗号字符串。  
    - 优先级：P0 已修。

14. **补货建议是嵌套结构**  
    - 现象：`query_fba_valid_list` 的 MSKU/可售天数在 `displayInfo.productList` / `suggestInfo.availableSaleDaysFba`，顶层没有 sku。按扁平字段映射会得到 0 行。  
    - 文件：`lingxing_sync.py` `replenish_to_row`。  
    - 优先级：P0 已修。

9. **广告花费摘要勿双重计数**  
   - 现象：`ad_campaign_report` 的 `spend_sum` 含汇总行时会翻倍。  
   - 影响：第一期不同步广告明细表。  
   - 优先级：P2，广告页时去掉 summary 行。

10. **本地 SKU ≠ 领星 MSKU**  
    - 现象：主键是领星 MSKU；不会静默改名。同 ASIN 不同 SKU 写入 `lingxing_sync_diff`。  
    - 文件：`lingxing_sync.py` listing 循环。  
    - 优先级：P1 已记录差异。

## 2026-09-19 评审落地

### 领星预览确认
Listing 不再直写 `product_master`。拉取后状态 `preview_pending`，主数据页按 SKU/字段勾选后 `POST /api/lingxing/sync/confirm` 做字段级 patch。英文名/品牌本地已有则默认不勾。同一 MSKU 出现在美加多家店铺时按 SKU 去重，优先保留美国站，避免 `lingxing_sync_preview_sku` UNIQUE 中止。

### 数据流
启动时把 `产品信息表.csv` 中主库空的报关字段灌进 SQLite（不覆盖）。发票/报关/STA/发货表/工人单/FNSKU 运行时不再读 CSV。Step1 已填外箱不覆盖，空值才补箱规和单箱装量。

### 排箱开源对照（不合入 3D）
对照 [gsisinna/3D-bin-packing-opt](https://github.com/gsisinna/3D-bin-packing-opt)（py3dbp，`fix_point` / `check_stable`）。本软件 `SkuRow.unit_volume_cm3()` 是外箱体积÷单箱装量，没有真实单品长宽高，3D 摆放会建立在假立方体上。默认保持贪心混装，不引入 py3dbp。有完整 `unit_*` 后再做 A/B。

### 启动脚本
根目录 `一键启动.bat` 照旧；新增 `一键重启.bat` → `scripts/restart_dev.ps1`，只杀 `.dev/ports.json` 中且命令行属于本软件的进程。前端端口被占时在 5173–5199 递增重试。
