## 1. 一句话架构

本地 Windows 单机工具：运营在浏览器里走 **Step 1 录入 → 2 排箱锁定 → 3 STA/内部表 → 3.5 可选刷仓 → 4 亚马逊 CSV+PDF 校验 → 4.5 发票 → 5 报关**。

```
浏览器 (Vite 开发 :5173–5199 / FastAPI 托管静态 便携版)
    │  fetch /api/*   （开发走 Vite proxy；便携版同源）
    ▼
FastAPI  backend/main.py:app = create_app()
    │  routers/*  →  services/*（仅 boxing/shipment/invoice）  →  fba_tool/*
    ▼
app_data/          可写：SQLite 主库、用户配置、任务历史、会话
backend/config/    出厂只读默认 JSON
backend/templates/ 出厂只读 Excel/CSV 模板
```

技术栈：

| 层 | 技术 | 入口 |
|----|------|------|
| 启动器 | Python + uvicorn | `run_app.py`（便携版 / 双击 exe） |
| API | FastAPI | `backend/main.py` → `create_app()` |
| 业务 | pandas / openpyxl / pdfplumber / PyMuPDF | `backend/fba_tool/` |
| UI | React 19 + TanStack Router + Vite（SPA） | `frontend/src/standalone-client.tsx` |
| 全局状态 | React Context | `frontend/src/context/workflow-context.tsx` |
| 主数据 | SQLite | `app_data/fba_master.db` 表 `product_master` |

Python 包名是 **`fba_tool`**（目录 `backend/fba_tool/`）。Windows 大小写不敏感，不要再引入第二套包名。

前端入口链：

```
vite.config.ts  tanstackStart.client = standalone-client ；server = server
standalone-client.tsx
  生产（HTML 有 window.$_TSR）→ hydrateRoot + StartClient
  开发（无 SSR 清单）→ createRoot + RouterProvider(getRouter())
router.tsx → routeTree.gen.ts
__root.tsx → WorkflowProvider + 主题 + Toaster
```

## 3. 进程、端口、静态资源

### 3.1 开发

- 推荐：仓库根 `一键启动.bat` → `scripts/start_dev.ps1`（自动找端口，写入 `.dev/ports.json`）。
- 后端扫描 **8000–8099**；前端扫描 **5173–5199**。只开后端：`scripts/start_backend.ps1`。
- Vite 把 `/api` 代理到 `http://127.0.0.1:<backend>`。端口优先级：`.dev/ports.json` 的 `backend` > 环境变量 `FBA_BACKEND_PORT` > **8002**。每次请求重读 ports 文件。
- `backend/main.py` 的 `__main__`：`0.0.0.0:8000` + reload。这不是便携版路径。
- CORS：`backend/settings.py` 白名单 5173–5175（127.0.0.1 与 localhost）+ regex `https?://(127\.0\.0\.1|localhost)(:\d+)?`。

前端 API 基址：`frontend/src/lib/api/client.ts` 的 `VITE_API_BASE_URL`（空则相对路径，开发靠 proxy）。JSON 超时 **30s**。`lib/api/routing.ts` 用原生 `fetch`，不走 `resolveApiUrl`。

开发 SPA：`vite.config.ts` 的 `spaDevShellPlugin` 对无后缀路径直接回 `index.html`，绕过 TanStack SSR 片段白屏。

### 3.2 便携版

1. `run_app.py`：UTF-8 控制台、单实例互斥 `Global\FBA_Smart_Tool_V1`、**HOST=`127.0.0.1`**、端口序列 **8002–8011 再 18002–18019**，写入数据目录下的 `.server_port`。
   - 环境变量 `FBA_APP_DATA_DIR`：设置后数据目录（`_data_dir`）改用该路径，`.server_port`、主库、配置都写到那里（测试/冒烟用临时目录，绝不碰真实 app_data）。
   - 环境变量 `FBA_NO_BROWSER=1`：服务就绪后不自动打开浏览器。
2. 健康检查：`GET /api/health`。
3. 数据目录：默认 exe 旁 `app_data/`，`FBA_APP_DATA_DIR` 可覆盖（`fba_tool/app_paths.py`：frozen 时 `project_root` = exe 目录）。
4. 静态页：PyInstaller `_MEIPASS/dist`；开发未同步时 `backend/dist`。
5. SPA 挂载：`main.py` 的 `_mount_frontend_spa`（必须在全部 `/api` 路由之后）。
   - `/assets` → `_AssetStaticFiles`（js/css 长期缓存）
   - `GET /` → `index.html`（没有则回退 `_shell.html`），`Cache-Control: no-cache`
   - `GET /{catchall}`：`api/`、`assets/`、`docs`/`redoc`/`openapi.json` → 404；**路径含 `.`** 当静态文件，找不到 404（绝不回 index 当 JS）；无点号 → `index.html`

便携包内启动器是 **`启动FBA工具.bat`**（`finish_portable_dist.py` 生成），不是仓库根的 `一键启动.bat`。

## 4. 分层与调用方向

```
UI 组件 (stepN-workspace.tsx)
  → hooks/use-*.ts
    → lib/api/*.ts
      → FastAPI routers/*.py
        → services/*.py          （仅 boxing / shipment / invoice）
          → fba_tool/*.py        （算法、解析、Excel/PDF、SQLite）
```

**只有** `boxing.py` / `shipment.py` / `invoice.py` 三个 router 走 `backend/services/`。其余 9 个 router（step1、export_step3、routing、master_data、config、customs、forwarders、tasks、pdf_tools）直接调 `fba_tool`。health 两者都不调。

`routers/routing.py` 里有文件名解析、多 CSV 合并排序（`extract_warehouse_from_filename` / `extract_ticket_rank`），编排较厚。boxing 的 `/box_metrics` 也不走 `boxing_response_payload`，直接调 `boxing_api_compliance`。

Pydantic：`backend/schemas/` — `step1.py` `boxing.py` `invoice.py` `customs.py` `config.py` `master.py` `tasks.py` `shipment.py`。货件校验实际用 **multipart Form**，`schemas/shipment.py` 的 `ShipmentValidateRequest` **未被路由使用**。刷仓导出 body 在 `routing.py` 内联 Pydantic。

下载响应：`backend/utils/responses.py` 的 `xlsx_response` / `pdf_response` / `file_response`。`routing.py` 写的是 `from routers.shipment import xlsx_response`（shipment 模块再导出，能跑；改下载头请改 `utils/responses.py`）。

`create_app()` 启动时：`ensure_app_data_layout()` + `init_master_db()`。

`_ROUTERS` 注册顺序：health → config → master_data → tasks → step1 → boxing → export_step3 → shipment → pdf_tools → invoice → forwarders → customs → **routing（最后）**。

## 5. 工作流状态机（前端是权威）

后端 **无** 跨步骤工作流引擎。每步 API 无状态；浏览器把 `rows` / `box_editor` / 文件 / 发票草稿带来带去。

### 5.1 步骤 ID 与挂载

| id | 界面 | 组件 | Hook / 逻辑 | 挂载方式 |
|----|------|------|-------------|----------|
| 1 | Step 1 录入 | `step1-workspace.tsx` | `hooks/use-step1-logic.ts` | 始终挂载，CSS `hidden` |
| 2 | Step 2 排箱 | `step2-workspace.tsx` | `hooks/use-box-validation.ts` | 同上 |
| 3 | Step 3 导出 | `step3-workspace.tsx` | `hooks/use-step3-export.ts` | 同上 |
| 3.5 | Step 3.5 刷仓（可选） | `step3-5-routing-workspace.tsx` | **组件内** + `lib/api/routing.ts` | 同上。Step3「下一步」进 **4** 不是 3.5。组件 **import 了 `StaleDataBanner` 但未渲染**，只靠 `staleness.routing` 禁下载 |

壳层：`app-shell.tsx`（侧栏、主题、步骤门禁）。侧栏 DeepSeek **密钥/模型/温度** 在「系统设置」：`app-sidebar.tsx`。Step 1 只有 **DeepSeek 智能解析按钮**（`use-step1-logic` 无 key 时会提示去侧栏填）。

### 5.2 导航门禁（`workflow-steps.ts`）

`canEnterStep(target, current, state)`：

- `target === current` → 允许
- `target < current` → **一律允许回退**（不看水位）
- `target <= highestReachedStep` → 允许回看
- 从未到过：
  - ≥2：至少一条 `sku.trim() && Number(totalQty) > 0`
  - ≥3 且 **&lt;4.5**（含 3.5、4）：`boxLocked && boxEditorApi.length > 0`
  - **仅 4.5 / 5**：需要 `step4Ok`（进 Step 4 本身不需要已校验通过）

`inferHighestReached`：

- `step <= 3`：水位抬到当前 step
- `step > 3`：仅当 `saved >= step` 或已有 `step4Ok` / 发票 / 报关 才把水位抬到当前 step
- `boxLocked` → 至少 3；`step4Ok` → 至少 4；有发票会话 → 4.5；有报关 data → 5
- **过期不会把水位打回去**

运行时 Context 另有一条：`setHighestReachedStep((h) => (step > h ? step : h))`，**不经** `inferHighestReached`，人一进当前步就会抬水位。恢复 localStorage 草稿时 `inferHighestReached` **不传** `hasInvoice`/`hasCustoms`；从任务历史/`fbox` 加载时才传。测试：`{ step: 5, boxLocked: true, step4Ok: false }` 仅用 infer 得到 **3**。

### 5.3 失效链（过期 ≠ 清空）

`frontend/src/lib/workflow-invalidation.ts`

阶段顺序：`input → boxing → export → routing → validation → invoice → customs`

- `invalidateFrom(stage)` / `markStale(stage)`：把 **该阶段之后** 标 stale，**不改 stage 自身**
- `clearStageStale`：只清当前阶段
- `clearStaleFrom`：从该阶段起到末尾全清（Context 已暴露；现行 hook 几乎不用）
- `isOfficialExportBlocked(stage)`：`Boolean(staleness[stage])`

Step 1 字段：`workflow-input-change.ts`

- `BOXING_INPUT_FIELDS` = `sku totalQty perBox l w h unitKg emptyKg grossKg` → `markStale("input")` 且 **解锁排箱**
- `fnsku` 或 `dataSource` → `markStale("export")`（不必重排箱、不解锁）

锁定排箱：`use-box-validation.ts` 的 `lockPlan` —— `setBoxLocked(true)` + 清 Step 3 矩阵计数 + `markStale("boxing")`，**不擦 Step 4+ 数据**。

过期横幅：`components/stale-data-banner.tsx`。Step 1 顶栏永无琥珀点。

正式文件（`OFFICIAL_FILES_BY_STAGE`）：

| stage | 正式文件 |
|-------|----------|
| input / boxing | （无） |
| export | 内部留档表、Send to Amazon 模板 |
| routing | 刷仓货代表 |
| validation | 工人装箱贴标实操单、发货表、货代表、热敏箱唛 |
| invoice | 货代发票 |
| customs | 报关资料 |

谁标 stale / 谁清（以源码为准）：

| 触发 | 调用 | 实际效果 |
|------|------|----------|
| Step1 改装箱字段 | `markStale("input")` + 解锁 | boxing…customs stale |
| Step1 改 FNSKU / dataSource | `markStale("export")` | export…customs stale（boxing 不清、不解锁） |
| Step1 增删行 | `markStale("input")` + 解锁 | 同装箱字段 |
| 解析 / 整表清空 | `resetDownstreamFromInput()` | **擦除**下游数据 + 清全部 stale + `highestReachedStep=1` |
| Step2 重算成功 | `clearStageStale("boxing")` | 只清 boxing 旗 |
| Step2 锁定方案 | `markStale("boxing")` + 清 Step3 矩阵 | export…customs stale |
| Step3 预览成功 | `clearStageStale("export")` | |
| Step3.5 预览成功 | `clearStageStale("routing")` | |
| Step4 重置校验 / 改装箱模式 | `setStep4Ok(false)` + `markStale("validation")` | **只把 invoice+customs 标 stale**；`staleness.validation` 仍为 false，顶栏 Step4 琥珀点不一定亮 |
| Step4 校验通过 | `clearStageStale("validation")` | |
| Step4.5 **填充**成功 | `clearStageStale("invoice")` | **导出成功不清** invoice 旗 |
| Step5 预览成功 | `clearStageStale("customs")` | |

下载守卫：

- Step 3：`isOfficialExportBlocked("export") \|\| !boxLocked`
- Step 3.5：直接 `if (staleness.routing)`
- Step 4：`isOfficialExportBlocked("validation")`

## 12. 遗留与陷阱（改错地方的常见原因）

1. **旧 Streamlit 整页已归档到 `backend/legacy_streamlit/`**（`app.py` 及 `fba_tool/session_ui` / `settings_ui` / `product_catalog_ui` / `perf_cache`）。现行入口是 `run_app.py` + `backend/main.py`。
2. **双产品目录**：SQLite `product_master` vs `产品信息表.csv`。FNSKU、报关名、工人单品名可能来自不同源。
3. **中文列名是协议**。FNSKU 是可选列，不要写进 `REQUIRED_COLUMNS`。
4. **`fba_parser.py` vs `shipment_parser.py` vs `forwarder_quote.py`**：新校验走 shipment_*；货代表实现只在 `forwarder_quote`；`fba_parser.build_forwarder_df` 是再导出。
5. **刷仓 CSV** 必须 `allow_unassigned_fba=True`。
6. **打包白屏** 几乎总是 `_shell.html` / `$_TSR` / `mapDeps` 双斜杠。
7. **不要把 `backend/dist` 里的旧 FBAWizard onedir 打进包**。
8. 顶栏版本文案：`app-header.tsx`「U盘便携版 V3.2」。发布改版本还要改 `backend/fba_tool/app_version.py`、`finish_portable_dist.py` 的 `RELEASE_VERSION`、`build_standalone.ps1`、`run_app.py`、spec 与 `packaging/使用说明.txt`（`backend/test_v32_version.py` 核对）。
9. **`一键启动.bat` = 开发**；便携版是包内 `启动FBA工具.bat`。
10. `fba_tool` 并非完全不碰 FastAPI：出口商/货代注册抛 `HTTPException`。
11. Step 4 换文件/模式 **不会** 把 `staleness.validation` 设为 true。
12. Step 4.5 **导出不清** invoice 过期旗，只有填充成功才清。
13. `lib/api/routing.ts` 不走 `VITE_API_BASE_URL`。
14. 旧文档（`backend/docs/一键打包指南.txt`、`packaging/工作流与运行逻辑_V1.2.txt`、`backend/README.md` 打包节）端口/包名/static 目录已过时。
15. `BoxEditorRequest.max_mixed_items` / `max_weight_kg` **API 不生效**；改混装上限只改 `user_settings.json` / `user_config`。
16. `schemas/shipment.py` 的 `ShipmentValidateRequest`、`schemas/customs.py` 的出口商 body **未被对应 router 使用**（出口商在 `routers/config.py`）。
17. 主库注释写合并 ASIN，`apply_master_to_input_rows` **不做**；`upsert_product` INSERT 漏 `qty_per_box`。
19. Step 3 改 FNSKU 显示不要只改 `resolve_fnsku`：内部留档/STA 走 `load_static_fnsku_map`。
20. `pdf_validator.py` 已无引用，改 PDF 解析去 `shipment_parser`。
21. 产品信息表 `lookup` 模糊匹配可能串 SKU；主库不会。
