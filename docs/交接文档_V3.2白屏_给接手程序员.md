### 1.3 可能的原因（按可能性排序，全部是推测）
1. **推测**：干净 clone 里重新生成的前端产物和以前不一样（例如 `routeTree.gen.ts` 重新生成、`_shell.html` / `index.html` 选的入口不同，见 `scripts/sync_frontend_static.py` 的 `_pick_client_entry`），导致静态 shell 和客户端首次渲染的 `<html>` 结构不一致，触发 React #418，整页水合失败、页面空白。
2. **推测**：S9 期间前端根路由（`frontend/src/routes/__root.tsx` 一类文件）或某个首屏组件的改动，让服务端 shell 和客户端渲染出的文字 / 属性不一致（#418 的典型原因：时间、随机数、`typeof window` 分支、浏览器扩展改了 DOM）。
3. **已基本排除**：静态文件没打进包、白名单 `packaging/release_manifest.py` 漏了前端——E4、E6 说明前端文件都在、都能取到（前端目录是 spec 里单独的 `(BACKEND/dist, "dist")` 条目，不走白名单）。
4. **本机已排除，其他电脑未验证**：JS 被当成 text/plain。用户电脑上 JS 返回的是 `application/javascript`。
5. **可能性低（推测）**：出厂配置清空（映射 `{}`、出口商档案为空）或 `default_brand` 为空导致前端报错。E7 的错误发生在水合阶段，和这些接口数据关系不大，但没验证。

- **目录**（仓库根：`C:\Users\huang\Desktop\FBA_Smart_Tool_Cursor2026.7.1\FBA_Smart_Tool_Cursor`）：

  - `packaging/`：`FBA_Smart_Tool.spec`、`release_manifest.py`（打包白名单）、`build_release_templates.py` 和 `release_templates/`（DEMO / 空白版模板和配置）、`使用说明.txt`。
  - `scripts/`：`build_standalone.ps1`（一键打包）、`finish_portable_dist.py`（生成 zip）、`smoke_e2e.py`（冒烟）。
  - `run_app.py`：便携版启动器（只绑 127.0.0.1，端口 8002 起）。

  - `FBA_ALLOW_LEGACY_MIGRATION`：开发模式下设 `1` 才从旧路径迁移数据；打包版默认迁移（exe 旁的旧 `fba_master.db`、`config/` 搬进 `app_data`），设 `0` 关闭。设了 `FBA_APP_DATA_DIR` 或在 pytest 里一律不迁移。
