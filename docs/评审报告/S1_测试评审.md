## 二、缺陷

### D1【中】从工作流程 ID 里误识别仓库代码，错误的仓库写进报关单备注
- **位置**：`backend/fba_tool/shipment_parser.py` L94（`_warehouse_from_name(shipment_name) or _warehouse_from_name(_scan_text(rows))`）、L505–520（`_warehouse_from_name`）。这是 S1 之前就有的代码，S1 没改过，但会影响 S1 的冒烟验收和报关导出。
- **复现**：`parse_csv_shipment(open('test1/第一票ONT8.csv','rb').read(), allow_unassigned_fba=True).warehouse_code` 返回 `'BF26'`。原因是工作流程名称 `wfbe6bd412-8baa-4543-bf26-…` 里的 `bf26` 被当成了仓库代码。5 票全部是这样。导出后报关单!B16 是“仓库编码：BF26。FBA编码：待分配。”
- **期望**：货件名称是“待分配”时，仓库应该留空或标 UNKN，并提示用户补；也可以按方案 3.1 用“配送地址 + 文件名”临时标识（文件名里有 ONT8/AVP1/MDW2/LAX9/TOL3）。识别仓库时不要扫描工作流程 ID 这类 UUID 字段。

### D2【中】多张“待分配”货件合并报关时，箱号互相冲突，件数和净重算错
- **位置**：`backend/fba_tool/customs_package.py` L509–524（`_count_total_boxes` 用 `(shipment_id, 箱号)` 去重）。S1f 开始用这个箱数计算净重（毛重 − 0.2×箱数），所以错误会带进净重。
- **复现**：用 test1 五票一起 `build_customs_data(...)`，结果 `total_pieces = 34`、净重 = 840.9 − 0.2×34 = 834.1。正确值应是 145 箱、811.9。把 5 票的 shipment_id 改成不同的值后，结果就正确了：145 / 840.9 / 811.9。
- **建议**：去重键改成 `(id(pair) 或 文件序号, 箱号)`，或者禁止“待分配”的票合并报关并提示用户；补一条多票“待分配”的用例。

### D3【中】Excel 样表导入仍然静默填 0、接受负数
- **位置**：`backend/fba_tool/data_processing.py` L195 `load_from_excel` → L445–463 `_to_int` / `_to_float`。
- **复现**：用 openpyxl 生成一个样表，“发货总数” = abc，“单箱装量” = -5。导入后得到 `{'发货总数': 0, '单箱装量': -5}`，没有任何报错。
- **说明**：交接清单第 6 节已经把它列为“待办（不阻塞）”，但方案 S1③ 对应的 3.1 验收（第 2、4 条，以及“不得静默变 0”）没有达到。S1 不能算完整验收。

### D4【低】GBK 编码的 CSV 无法导入，而且报错信息有误导性
- **位置**：`shipment_parser.py` `parse_csv_shipment`（L88 起）。
- **复现**：把 test1 第一票转成 GBK 编码后导入，报 `ValueError: CSV 未找到「箱号」行或 FBA...U 映射`。真实原因是编码不对，提示里却没提。
- **建议**：依次尝试 UTF-8-SIG、UTF-8、GBK 解码（方案 3.1 有这条要求）；都失败时提示“编码无法识别”。

## 三、观察项（不扣分）
- 用逗号分隔、同时又带千分位的行（`SKU-A,1,000,20,…`）会报“单箱装量必须大于 0，现在是 000”。没有静默填 0，但提示容易误导。建议在“逗号分隔且某个字段是 3 位纯数字”时提示“可能是千分位，请用 Tab 分隔”。
- 启用口令后，GET 接口也要口令（比方案“非 GET 要口令”更严格），可以接受。`/api/auth/login?token=…` 会把口令放进 URL，uvicorn 的访问日志可能会记下来，建议改用 POST 或在日志里脱敏（方案 3.7 有日志脱敏要求）。
- `placement_fee.py` 的 CM_TO_IN、KG_TO_LB 改成了精确值（L9–10），这会让仓储配置费的估算结果有很小的变化。建议在交接清单里注明。
- 有几个文件的 index 从 CRLF 变成了 LF，所以 `git diff --stat` 显示整个文件都改了（例如 placement_fee.py 显示 1033 行）。建议加 `.gitattributes`，或者评审时用 `--ignore-cr-at-eol`。
