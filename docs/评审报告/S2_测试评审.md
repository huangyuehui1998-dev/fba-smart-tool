### D1【中】MCP 预览确认会覆盖手填的 FNSKU
- **位置**：`fba_tool/lingxing_preview.py` L311–329 的 `apply_lingxing_field_patch`。非价格字段直接用 `upsert_product(rec, overwrite=True)` 写入，没有查 field_source。
- **复现**（probe11 的 C 段）：
  1. 用 `patch_product_field(S1, "fnsku", "X00MANUAL1")` 手填，这个字段的来源记为 manual；
  2. 调用 `apply_lingxing_field_patch(S1, ["fnsku", "listing_price"], {"fnsku": "X00MCPFNSK", ...})`；
  3. 结果 fnsku 变成 X00MCPFNSK，但 field_sources 里仍然写着 `fnsku: manual`。
- **影响**：同一个手填字段，走领星文件导入会被锁住，走 MCP 预览确认却会被覆盖，两条路径规则不一致，而且来源记录和实际数据对不上。
- **建议**：非价格字段也走 `set_product_fields(..., SOURCE_LINGXING)`，或者遇到 manual 字段时在预览里标 locked。补一条测试。

### D2【中】申报价回落时没有警告，没有价格时报关单价静默变成 0
- **位置**：
  - `product_fields.py` 的 `resolve_declared_price` 只返回价格和来源；
  - `master_db.py` L1090–1095 写了“申报价来源”，但全仓库没有任何地方读取它；
  - `customs_package.py` L285–290 在没有价格时 `unit_price = 0.0`，不报错也不提示。
- **复现**（probe11 的 D 段）：legacy 时返回 (9.99, "legacy")，没有价格时返回 (None, "")，两种情况都没有产生任何警告。
- **建议**：来源是 legacy 时提示“申报价来自旧数据，未经领星核实”；没有价格时导出阻断或标红。另外交接清单里提到的“29.99 → 15.99 大幅下降，待确认”，也应该在导出时提示。

### D3【低】仓库白名单里加了查不到的代码，注释也有错
- **位置**：`warehouse_codes.py` L27–28。
- **问题**：
  - TOL2、DAY1 在公开仓库列表里查不到；
  - CVG3 实际在 Hebron, KY，却写在“OH”注释下；
  - 这段 OH 代码插在“# AZ”注释下面，注释位置也乱了。
- **影响**：白名单越宽，用文件名误识别仓库的可能越大。
- **建议**：删掉 TOL2 和 DAY1（或者注明来源），改正注释。

### D4【低】领星映射有两处小问题
- `listing_to_product` 没有映射 `local_name`：样例里有中文品名，同步结果却是 None。可是 `lingxing_field_map.json` 里已经声明了 local_name。
- 记录里只有 `currency_symbol="$"` 时，币种会存成 `"$"`，不是 ISO 代码 USD（`map_listing_row({"msku":"Z2","currency_symbol":"$",...})` 可以复现）。
