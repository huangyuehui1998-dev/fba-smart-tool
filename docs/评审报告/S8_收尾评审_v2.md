## 二、新缺陷

### N6【轻微 −0.2】常规价只比促销价略高（不到 5%）时，会盖住并覆盖近期非促销价
- **位置**：`product_fields._track_nonpromo` / `normal_price`。只要 regular_price 高于售价，就当作“有信息”，优先使用，不再看 last_nonpromo。
- **复现**（探针 `edge_obs`）：先同步 16/16，再同步售价 12、regular 12.5。
  - 申报 (12.0, lingxing)，没有提示；
  - 数据库里 last_nonpromo **从 16 被改成 12**。
- **评估**：真实样本里 regular 都等于售价，这种情况少见；按 D-12 的字面顺序（常规价优先）也不算违规，所以只扣轻微分。
- **建议**：记录非促销价时，参照值取 max(有效常规价, 近 90 天非促销价)，促销价才不会覆盖历史。是否也把正常价改成取两者较大值，属于 D-12 参数细节，按“由我们判断”的授权可以做，但要在决策记录里注明“Bot 选的参数，用户可改”。

### N7【轻微 −0.3，测试有效性，不是产品缺陷】测试顺序依赖：开发方说的 sqlite 报错已复现
- **复现**：
  - `pytest test_s8fix2_dec12_real_sample.py test_s8fix1_dec12_e2e.py test_s8_fix.py`：2 failed / 44 passed；
  - 把 `test_s8fix1_dec12_e2e.py` 放在 `test_s8_fix.py` 前面也一样；
  - 失败的两条：
    - `test_s8_fix.py::test_hs_presets_endpoint_and_not_auto_seeded`：`no such table: hs_declare_template`
    - `test_s8_fix.py::test_d11_duplicate_sku_rows_rejected`：`no such table: product_master`（`master_db.py:557` `get_product_by_sku`）
  - 按开发方的顺序（test_s8_fix 在前）46 passed；在仓库根目录跑也通过；全量 687 passed。
- **原因**：
  - `main.py` 第 208 行 `app = create_app()` 在**导入时**执行 `init_master_db()`。
  - D-12 的 e2e 测试在 `env` fixture 里（数据库已被 monkeypatch 指向 tmp_path）第一次 `from main import app`，表建在那个临时库里。
  - fixture 结束后，数据库路径恢复为 conftest 的全局临时目录，但 `main` 已缓存在 `sys.modules`，不会再初始化，所以全局临时库一直没有建表。
  - 后面 test_s8_fix 用 TestClient 或直接读库，就报 no such table。
  - 全量能过，只是因为前面恰好有别的测试已经初始化过全局目录。
- **定性**：测试隔离问题（导入时的副作用加上共享全局状态），不是产品缺陷。产品进程启动时只导入一次 main，数据目录是固定的。
- **建议**：
  - conftest 加一个 session 级 autouse fixture，对全局临时目录执行 `init_master_db()`；
  - 或者让依赖库表的测试自己初始化；
  - 并加一项打乱顺序（如 `-p randomly`）或倒序的 CI 检查。
